引言：为什么是 Hexo + Butterfly？

在内容平台林立的今天，拥有一个完全自主可控的个人博客，依然是技术人沉淀知识、展示自我的最佳方式。Hexo 凭借其基于 Node.js 的极速生成能力与纯粹的 Markdown 写作体验，成为了静态博客领域的首选框架。而 Butterfly 主题，则像是为这把利器配上了一副精致的刀鞘——它不仅在视觉上提供了现代化的卡片式设计与流畅的过渡动画，更在功能层面集成了搜索、评论、数学公式、流程图等一整套开箱即用的解决方案。本文将从环境配置开始，手把手带你完成 Hexo 的初始化，并深入 Butterfly 主题的核心配置层，完成从“能看”到“好看”的蜕变。

第二阶段：创建博客专用的GitHub仓库

本地环境配置好之后，我们需要在GitHub上建一个“云端仓库”来存放我们的博客代码。
登录GitHub账号，点击页面右上角的+号，选择New repository(新建仓库)。

极其重要的一步：仓库的名称必须严格按照你的用户名.github.io的格式来填写。例如，如果你的GitHub用户名是zhangsan,那么仓库名就必须是zhangsan.github.io。因为GitHub Pages会自动识别这种特殊命名的仓库，并把它作为你的个人主页发布。

在创建这个仓库时，有几个关键设置必须注意：
1.选择Public(公开):这是GitHub Pages免费版的基本要求，私有仓库无法免费托管网页。
2.保持空仓库状态即可，后面我们会通过Hexo自动把本地内容推送到这里。

第三阶段：初识Hexo静态博客框架

GitHub 仓库准备好之后，我们正式进入博客搭建的核心环节——学习 Hexo 静态博客框架。

为什么选择 Hexo 来搭建自己的技术博客？
简而言之，它足够轻量且强大——不用买服务器、不用装数据库，你只需要会写 Markdown 文章，它就能快速为你生成一个精美的静态网站。而且完全免费，可以直接托管在我们刚刚建好的 GitHub Pages 上。

接下来，我们就从零开始，一步步把 Hexo 安装到本地，并准备部署上线。

Hexo: Node.js 驱动的静态博客框架

Hexo 是一个快速、简洁且高效的静态博客生成框架。你只需要用 Markdown 写文章，Hexo 就会自动帮你把文字转换成完整的静态网页。

它的工作方式非常简单，相比 WordPress 这类需要数据库和服务器的动态博客，Hexo 生成的是纯静态文件，加载速度快、安全性高，而且可以免费托管在 GitHub 上。

它的四大核心特点如下：

  • ⚡ 极速生成：基于 Node.js，哪怕有数百篇文章也能秒级生成。
  • 📝 Markdown 写作：支持完整的 Markdown 语法，让你专注内容创作。
  • 🎨 丰富主题：拥有上百款开源主题，一键即可切换博客外观。
  • 🚀 一键部署：只需一条命令，即可将文章发布到 GitHub Pages。

总结：不需要买服务器、不需要数据库，只要你有一台电脑，会打字，就能用 Hexo 搭建出极具极客范儿的个人博客。

Hexo 的工作流程：从 Markdown 到在线博客

核心概念：Hexo 本身只是一个本地生成工具，它不提供在线服务。你在本地电脑上完成写作、预览、生成，最后把生成的静态文件推送到 GitHub Pages，由 GitHub 负责对外提供访问。整个过程不需要自己的服务器。

Hexo 的工作流程可以清晰地分为以下四个步骤：

  1. ✍️ 写文章
    在本地博客的 source/_posts 目录里，用 Markdown 语法编写文章。

  2. 👀 本地预览
    运行 hexo server（或简写 hexo s）命令。在浏览器输入 http://localhost:4000，就能实时看到博客的效果，方便修改。

  3. ⚙️ 生成静态文件
    运行 hexo generate（或简写 hexo g）命令。Hexo 会把所有 Markdown 文件转换成 HTML 网页文件，并统一放在 public 目录里。

  4. 🚀 部署上线
    运行 hexo deploy（或简写 hexo d）命令。把 public 目录里生成好的静态网页文件，推送到我们刚才创建的 GitHub 仓库中。随后全世界的人就能访问你的博客了。

第四阶段：环境准备与安装

安装 Node.js

为什么需要 Node.js？
因为 Hexo 是基于 Node.js 开发的框架，所以必须先安装 Node.js 运行环境。建议下载 LTS（长期支持版），这个版本最稳定可靠。

安装步骤：

  1. 访问 Node.js 官网 下载 LTS 版本的安装包。
  2. 双击下载好的安装包，一路点击“Next”进行默认安装。
  3. 注意：安装过程中，请确保勾选了 Add to PATH 选项（通常默认就已勾选），这样系统才能识别到命令。
  4. 安装完成后，务必重启 Git Bash（如果你之前开着，一定要关掉重新打开），否则它识别不到新安装的命令。
